05 — Rules

Do's and don'ts

Five rules each. If a decision is not covered here, the default is the quieter option.

Do
  • Use indigo (#6366F1) only for interactive elements — never for decoration or static text.
  • Maintain the 4px spacing grid for all padding, margins and gaps.
  • Use General Sans for headings and DM Sans for body — never swap them.
  • Keep kit cards at 12px radius and buttons/inputs at 6px — don't mix these values.
  • Provide sufficient contrast in both light and dark modes — test both.
Don't
  • Don't use pure black or pure white for text — use the defined palette values.
  • Don't add decorative gradients or illustrations — the interactive dot grid is the only decorative element.
  • Don't use shadows on static elements — reserve elevation for hover and focus states.
  • Don't use more than two font weights on a single screen.
  • Don't place more than one primary button in the same view section.

The format

One file, everything a team needs

A DESIGN.md is plain markdown with a fixed skeleton: overview, colours, typography, spacing, components and rules. It renders anywhere, diffs cleanly in a pull request, and gives a model the context to generate UI that actually matches.

Read the format See a real kit
DESIGN.md 
# Kit name
## Overview
  One paragraph on mood, audience, density.
## Colors
  - **Role** (#HEX): where it is allowed.
## Typography
  - Display / Body / Code, with sizes and weights.
## Spacing
  - Base unit, scale, container, gutters.
## Components
  - Buttons, inputs, chips, cards, nav.
## Do's and Don'ts
  - The five rules that settle arguments.
